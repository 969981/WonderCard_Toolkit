# WonderCard Studio i18n / 国际化开发规范

## UI 语言支持
- 第一批：简体中文 (`zh-CN`)、繁體中文 (`zh-TW`)、English (`en`)、日本語 (`ja`)。
- 第二批：Français、Deutsch、Italiano、Español、한국어（与游戏常见语言对应），所有新增语言必须完成文案覆盖检查与浏览器回归后才加入可见菜单。
- 每一种可见语言必须覆盖：静态标题、导航、字段标签、性格及 PID 等选项、字段帮助、确认/错误提示、审计结果、导出结果、无文件状态、无障碍标签。

## 架构要求
1. **UI locale != 礼物内语言字段**：切换界面语言不得修改 `fields.language`、`allowed_language`、Title/OT/Nickname、`raw_hex`、`baseline_fields` 或输出的 WC 二进制。
2. 统一翻译 key（`section.header`, `field.pid_type`, `error.date`），不可从中文正文做替换，不允许基于翻译后的字段名进行数据绑定。
3. 翻译要正确处理 `{n}`、`{field}` 等插值占位；构建时阻止缺键和占位符不一致。
4. UI 语言偏好可存 `localStorage['wondercard.ui.locale']`，存储不可用时仍必须正常运行；不得写入卡片或 JSON。
5. 使用 `textContent` 渲染普通翻译；在 `innerHTML` 模板中，用户数据及翻译必须转义。
6. 切换语言同步更新 `document.documentElement.lang`、页面标题、`placeholder`、`aria-label` 与动态表单。
7. 日期编码必须依据 **格式** 而非当前 UI 语言：WC6 YYYYMMDD，WC7 年份相对 2000；审计 CSV 列名稳定，避免不同语言生成不兼容列名。
8. 审计、回写与合法性规则必须完全与翻译解耦。没有完成翻译的新界面语言不能显示为“已支持”。

## 测试验收
- 对四种第一批语言依次切换，断言导航、字段、审计文案确实切换。
- 切换语言前后的原始文件、`source_sha256`、`raw_hex` 与输出 bytes 完全一致。
- 在日语与英文界面修改 WC6 阿尔宙斯日期（2015-03-17 -> 2015-03-19），仍仅有 `0x4C` 单字节差异；WC7 日期另测。
- JSON 无损往返与 Full 修改锁定逻辑不受 locale 影响。
- 浏览器离线使用，不允许第三方翻译服务请求或将用户文件发送网络。
- 新增语言经过键名及参数数量检测；静态构建可验证 4 种已支持语言完全覆盖。
- UI 与 CLI 错误文本可以翻译，机器输出保留稳定错误代码供自动化审计。
